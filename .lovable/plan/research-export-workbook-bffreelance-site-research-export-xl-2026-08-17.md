# Research Export Workbook: BFFreelance_Site_Research_Export.xlsx

A read-only academic export. No application, database, design, or deployment changes. The workbook is written to `/mnt/documents/BFFreelance_Site_Research_Export.xlsx` and delivered as a downloadable artifact.

All content describes the Beth Frankos Freelance LLC site. FairStayOhio is dropped entirely — no records for it exist in this workspace.

## Case Context block (top of Project Summary tab)

- Project unit: Beth Frankos Freelance LLC customer-facing website/platform
- Organizational context: solo-operator professional services business offering operations consulting, business setup, and website design/management services (as described in accessible project records only)
- Study scope: agentic-AI-assisted development process, not business-performance evaluation
- Evidence period: earliest accessible chat record through the most recent record in this workspace; exact calendar boundaries recorded as unknown or inferred where chat timestamps are unavailable
- Evidence limitations: no independently verified stakeholder feedback, usage data, financial outcomes, or security-audit results

## Tabs

1. Project Summary — Case Context block, then business problem, intended users, system scope, main features, current status
2. Timeline — dated or sequence-ordered development events; exact dates marked unknown/inferred where no timestamped record exists
3. Human and AI Work — per work item: what the agent generated or changed vs. what the human specified, decided, tested, corrected, or verified
4. Major Changes — meaningful revisions, rework, errors, troubleshooting, requirement changes
5. Research Evidence — each accessible source record and what it demonstrates
6. Suggested Patterns — split into two clearly separated blocks: Documented Patterns (each backed by two or more distinct source records, with both cited) and Possible Patterns Requiring Researcher Review (single-record or indirect support)
7. Missing Information — what this project cannot establish: stakeholder feedback, actual use, business outcomes, security/privacy outcomes, cost/time data

## Evidence and sourcing rules

- Every row on every tab carries a specific Source value: chat segment reference, file path (for example `src/components/InquiryFormSection.tsx`, `.github/workflows/jekyll-gh-pages.yml`), memory file name (for example `mem://features/paypal-integration`), edge function path, or configuration file path.
- No invented facts, dates, opinions, revenue, costs, adoption, time savings, or performance figures.
- `unknown` where evidence is absent; `inferred` only where an indirect clue supports the entry, with the clue named.
- No API keys, tokens, passwords, customer data, personal data, or confidential values. Contact email and public pricing already published on the live site are treated as public.
- Known limitation stated in the workbook: no dated git/version history is accessible, so Timeline ordering is derived from chat sequence rather than verified commit timestamps.

## Technical notes

- Generated with a Python script using openpyxl, run from `/tmp`; only the output file is written to `/mnt/documents`.
- Arial throughout, bold header rows, frozen header panes, wrapped text, sized columns for readability.
- Evidence gathering is read-only: existing codebase context, project memory files, chat history search, and repository configuration files.
- Every page of the finished workbook is rendered and visually inspected before delivery; issues are fixed and regenerated.
